# kimman-ai.pages.dev 정밀 분석

- 대상: https://kimman-ai.pages.dev/
- 분석일: 2026-11-11
- 분석 방식: 공개 화면·텍스트를 기반으로 한 clean-room / evidence-first 분석
- 목적: 초등 AI·정보교육 웹앱을 설계할 때 재사용할 수 있는 **수업 구조, UI/UX, 상태 흐름, 알고리즘, 개인정보 설계** 추출

> 이 문서는 소스 코드를 직접 확보한 역공학 문서가 아닙니다. 따라서 실제 화면에서 확인되는 사실, 사이트가 스스로 밝힌 내용, 기술적으로 합리적인 추정을 구분해 기록합니다.

## 1. 한눈에 보는 서비스 구조

이 사이트의 핵심은 네 개의 앱을 따로 배치한 것이 아니라, **데이터 → 분류 원리 → 학습·평가 → 책임 있는 이용**으로 이어지는 하나의 학습 경로를 만든 점입니다.

| 순서 | 앱 | 핵심 개념 | 학생이 하는 일 | 주요 성취기준 연결 |
|---|---|---|---|---|
| 01 | 픽셀 스튜디오 | 디지털 데이터, 픽셀, 이진화, 해상도 | 그리고 숫자로 바꾸고 다시 복원 | [6실05-04] |
| 02 | 몬스터 분류 카드 | 분류 규칙, 학습 데이터, 일반화 | 카드를 보여 주며 숨은 규칙을 추론시키기 | [6실05-05] |
| 03 | 가위바위보 실험실 | 수집-학습-시험-개선 | 손 사진을 모아 분류 모델을 만들고 시험 | [6실05-05] |
| 04 | 저작권 판정단 | 저작권·이용허락·공유 책임 | 조건을 판단하고 자기 작품의 이용 조건 만들기 | [6실04-02], [6실04-03] |

메인 페이지가 이 순서를 명시적으로 보여 주기 때문에 학생은 “앱 네 개”가 아니라 **AI가 만들어지고 쓰이는 전체 과정**으로 받아들이기 쉽습니다.

### 가장 중요한 설계 결정

1. **설치와 회원가입이 없음**
2. **학생 산출물을 서버로 보내지 않는 구조**
3. **카메라를 사용하는 앱을 하나로 제한**
4. **디지털 활동과 종이 활동지를 항상 연결**
5. **단순 설명보다 조작 결과가 수치로 바뀌는 것을 보여 줌**
6. **AI의 성공뿐 아니라 실패·편향·헷갈림을 일부러 경험하게 함**

## 2.2 카드형 앱 소개

각 앱 카드에는 기능 이름만 넣지 않고 다음이 함께 드러납니다.

- 성취기준 코드
- 언제 사용하면 좋은지
- 핵심 체험
- 앱으로 들어가는 링크

즉 “도구 설명”이 아니라 **수업 상황 기반 진입점**입니다.

## 2.3 수업 도구 묶음의 설계 철학

메인 페이지에서 반복되는 메시지는 다음 세 가지입니다.

- 학생 계정이 필요하지 않음
- 입력 자료가 외부로 나가지 않음
- 인공지능의 원리를 실제 조작으로 확인

학교 현장에서는 기능 수보다 이 세 요소가 채택 가능성을 크게 높입니다.

# 3. 픽셀 스튜디오 분석

URL: https://kimman-ai.pages.dev/pixel

## 3.1 화면 흐름

화면 상단에서 다음 여섯 단계가 제시됩니다.

1. 그리기
2. 숫자로
3. 짝 게임
4. 선과 칸
5. 색과 숫자
6. 사진도 숫자

이 순서는 매우 잘 설계되어 있습니다. 학생이 추상적인 “디지털 데이터”를 먼저 정의로 배우는 것이 아니라, **직접 그림을 만들고 → 숫자를 보고 → 반대로 숫자로 그림을 복원하고 → 실제 사진까지 확장**합니다.

---

## 3.2 1단계: 모눈 그림

### 관찰되는 기능

- 격자 칸을 눌러 칠하기
- 드래그해서 연속 칠하기
- 흑백 뒤집기
- 전체 지우기
- 현재 그림을 ‘담기’
- 담은 도안을 다시 불러오기
- 활동지 인쇄

### 데이터 구조 추정

가장 단순한 구현은 다음과 같습니다.

```js
const grid = [
  0,0,1,1,0,0,0,0,
  ...
];
```

8×8이면 64개의 0/1 값, 16×16이면 256개의 0/1 값으로 표현할 수 있습니다.

### 구현 포인트

- DOM `div` 64개보다 `CSS Grid`가 쉬움
- 칸 수가 커지면 `canvas`가 더 효율적
- pointerdown / pointerenter를 함께 사용하면 마우스와 터치 드래그를 통합할 수 있음

---

## 3.3 2단계: 그림 → 숫자

사이트는 칠한 칸을 1, 빈 칸을 0으로 대응시킵니다.

### 교육적으로 좋은 점

“컴퓨터는 그림을 숫자로 본다”를 말로 설명하지 않고 학생의 그림이 **즉시 같은 길이의 숫자 배열**로 변환됩니다.

이때 중요한 학습 포인트는 다음입니다.

- 그림 자체와 데이터 표현은 다름
- 같은 그림을 숫자열로 저장할 수 있음
- 칸이 많아지면 데이터도 많아짐

---

## 3.4 3단계: 줄여서 보내기

사이트는 연속된 0과 1을 묶어 길이로 표현하는 활동을 제공합니다.

예시 구조는 사실상 **Run-Length Encoding(RLE)** 학습입니다.

```
00011000
→ 3, 2, 3
```

### 의미

단순한 AI 체험 사이트에서 거의 다루지 않는 **데이터 압축**을 초등 수준의 조작으로 연결한 점이 좋습니다.

### 재구현 알고리즘

```js
function rleBinary(bits) {
  const result = [];
  let expected = 0;
  let count = 0;

  for (const bit of bits) {
    if (bit === expected) {
      count++;
    } else {
      result.push(count);
      expected = bit;
      count = 1;
    }
  }
  result.push(count);
  return result;
}
```

이 방식은 “항상 0의 개수부터 센다”라는 수업 규칙도 그대로 구현할 수 있습니다.

---

## 3.5 4단계: 숫자를 보고 비밀 그림 복원

학생에게 그림 대신 숫자를 주고, 1인 칸을 직접 칠하게 한 뒤 정답과 비교합니다.

### 핵심 UX

정답/오답 하나만 보여 주지 않고 오류를 두 종류로 분리합니다.

- 0인데 칠한 칸
- 1인데 비운 칸

이 구조는 뒤의 AI 수업에서 **false positive / false negative** 개념으로 확장하기 좋습니다.

---

## 3.6 5단계: 아날로그 선과 디지털 격자

학생이 자유롭게 선을 그은 뒤 격자로 바꾸어 봅니다.

### 좋은 점

같은 선도 격자 크기에 따라 결과가 달라짐을 직접 보여 줍니다.

- 큰 칸: 거칠지만 데이터가 적음
- 작은 칸: 더 세밀하지만 데이터가 많음

이는 해상도와 표본화 개념을 자연스럽게 보여 줍니다.

### 구현 추정

1. 자유 선은 `canvas`에 그림
2. 목표 격자 크기로 다운샘플링
3. 각 셀의 평균 밝기 또는 검정 픽셀 포함 비율 계산
4. 임계값을 넘으면 1로 처리

---

## 3.7 6단계: 실제 사진도 숫자로

### 관찰되는 기능

- 사용자 사진 파일 선택
- 예시 가위/바위/보 사진
- 8×8, 16×16, 24×24, 32×32 선택
- grayscale 숫자 0~255 표시
- RGB일 때 데이터 개수 설명
- 셀 hover 시 해당 값 표시

### 기술 구현 추정

브라우저에서 일반적으로 다음 흐름으로 구현할 수 있습니다.

```
<input type="file">
→ FileReader / URL.createObjectURL
→ Image
→ canvas.drawImage()
→ getImageData()
→ RGB → grayscale
→ grid preview
```

회색조는 예를 들어 다음과 같이 만들 수 있습니다.

```js
gray = 0.299 * R + 0.587 * G + 0.114 * B
```

다만 실제 사이트가 이 공식을 쓰는지는 확인되지 않았습니다.

# 4. 몬스터 분류 카드 분석

URL: https://kimman-ai.pages.dev/monster

## 4.1 화면 흐름

1. 특징 고르기
2. 팀 나누기
3. 카드 검사
4. 인쇄해서 놀기

별도의 “로봇 가르치기” 영역에서는 학생이 일부 카드를 몬봇에게 보여 주고, 나머지를 시험 문제로 사용합니다.

---

## 4.2 핵심 개념

몬스터는 다음과 같은 명시적 특징을 가집니다.

- 뿔
- 눈
- 다리
- 색
- 날개
- 꼬리
- 입

학생은 2~4개의 특징을 골라 카드 집합을 만들고 A/B 팀으로 분류합니다.

### 중요한 교육적 장점

실제 이미지 AI보다 먼저 **특징(feature)** 과 **레이블(label)** 을 눈에 보이는 형태로 분리해 줍니다.

---

## 4.3 ‘몬봇의 생각’은 무엇인가

화면에는 다음 상태가 나타납니다.

- 의심하는 규칙 수
- 버린 생각
- 남은 카드로 시험
- 함정 예시
- 이름표 실수

이 구조는 신경망 훈련이라기보다 **가능한 분류 규칙 후보를 유지하고, 사례를 볼 때마다 모순되는 규칙을 제거하는 방식**으로 보는 것이 가장 자연스럽습니다.

즉 교육적으로는 다음과 같은 **version space / hypothesis elimination** 모델에 가깝습니다.

```js
let hypotheses = allPossibleRules;

for (const example of trainingExamples) {
  hypotheses = hypotheses.filter(rule =>
    rule.predict(example.features) === example.label
  );
}
```

> 실제 사이트가 이 정확한 코드 구조를 쓰는 것은 확인되지 않았습니다. 다만 UI에서 “의심하는 규칙”과 “버린 생각”을 직접 표현하기 때문에 이 해석이 가장 잘 맞습니다.

---

## 4.4 ‘처음 보는 몬스터’의 역할

훈련에 쓰지 않은 몬스터를 별도로 남깁니다.

이것은 매우 중요한 설계입니다.

- 학습 데이터와 시험 데이터를 분리
- 규칙을 외웠는지 일반화했는지 확인
- 카드 수가 많다고 항상 좋은 학습이 되는 것은 아님

초등 AI 수업에서 흔히 빠지는 “학습 데이터로 다시 시험하기” 오류를 피하게 합니다.

---

## 4.5 일부러 잘못 가르치기

페이지는 학생에게 두 가지 미션을 줍니다.

### 잘 가르치기
적은 카드만 보여 주고도 올바른 규칙을 찾게 하기

### 골탕 먹이기
편향된 카드만 보여 줘 엉뚱한 규칙을 배우게 하기

이 대비는 **데이터 편향과 대표성 부족**을 말로 설명하는 것보다 훨씬 강력합니다.

---

## 4.6 이름표 실수

잘못된 레이블을 의도적으로 넣는 기능은 **label noise**를 체험시키는 장치로 볼 수 있습니다.

재구현 시 데이터는 다음과 같이 두 층으로 분리하는 것이 좋습니다.

```js
{
  monsterId: 12,
  features: {...},
  trueLabel: "A",
  trainingLabel: "B" // intentionally corrupted
}
```

# 5. 가위바위보 실험실 분석

URL: https://kimman-ai.pages.dev/rps

## 5.1 전체 흐름

1. 모으기
2. 학습하기
3. 시험 보기
4. 기르기

이 순서 자체가 간단한 머신러닝 프로젝트의 핵심 사이클입니다.

---

## 5.2 입력 데이터 수집

### 관찰되는 기능

- 카메라
- 전/후면 카메라 전환
- 이미지 파일 입력
- 가위/바위/보별 데이터 수집
- 한 클래스당 최대 20장
- 원본 사진이 아니라 24×24로 줄인 이미지 사용

24×24는 576개 셀입니다.

### 설계 장점

학생에게 원본 사진을 그대로 저장하는 대신, **모델이 실제로 보는 축소 데이터**를 썸네일로 보여 줍니다.

---

## 5.3 실제 학습 방식

사이트가 화면에서 명시하는 학습 과정은 다음입니다.

1. 24×24로 줄임
2. 색을 제거
3. 같은 손 모양 이미지를 겹쳐 평균 모습 생성
4. 현재 화면이 어느 평균 모습과 가장 닮았는지 비교

따라서 이 모델은 딥러닝 신경망보다는 **prototype / nearest-centroid classifier**에 가깝습니다.

### 재구현 가능한 구조

```js
model = {
  rock: average(images.rock),
  paper: average(images.paper),
  scissors: average(images.scissors)
}
```

분류 시에는 각 평균 벡터와의 거리를 계산합니다.

```js
function mse(a, b) {
  let sum = 0;
  for (let i = 0; i < a.length; i++) {
    const d = a[i] - b[i];
    sum += d * d;
  }
  return sum / a.length;
}
```

```
prediction = argmin(
  distance(current, rockMean),
  distance(current, paperMean),
  distance(current, scissorsMean)
)
```

> 사이트는 “닮은 정도”를 보여 주지만 정확한 거리 함수는 공개 화면만으로 확인되지 않았습니다. MSE, cosine similarity, normalized correlation 중 하나일 수 있으므로 구현 시 명시적으로 선택해야 합니다.

---

## 5.4 평균 모습을 시각화하는 UX

보통 교육용 분류기는 결과만 출력합니다.

이 도구는 학습 후 각 클래스의 평균 이미지를 보여 주기 때문에 학생이 다음을 추론할 수 있습니다.

- 데이터가 한 방향으로 몰리면 평균도 그 방향으로 흐림
- 배경이 섞이면 평균 배경이 모델 기억에 들어감
- 데이터가 적으면 평균 템플릿이 불안정함

**모델 내부를 시각적으로 노출한다는 점이 가장 좋은 부분 중 하나입니다.**

---

## 5.5 일부러 모델을 망가뜨리는 기능

사이트는 다음 실험을 유도합니다.

- 한 종류 데이터만 5장 남기기
- 전체 데이터를 절반으로 줄이기
- 손을 기울이기
- 다른 배경에서 시험하기
- 다른 사람 손으로 시험하기

### 교육적 의미

일반적인 AI 수업은 모델을 “성공시키는 것”에 집중합니다.

이 도구는 반대로 **의도적으로 실패시키고 원인을 관찰**하도록 합니다.

이는 다음 개념과 직접 연결됩니다.

- 데이터 부족
- 데이터 다양성
- distribution shift
- 배경 편향
- 과적합의 직관
- 일반화

---

## 5.6 10문제 시험

시험은 학생이 실제 손 모양을 먼저 정한 뒤 AI 판정을 받도록 구성됩니다.

결과는 단순 점수 외에 **헷갈림 표**로 정리됩니다.

이는 실제 머신러닝의 confusion matrix를 초등 수준으로 번역한 구조입니다.

### 데이터 구조 예시

```js
confusion = {
  rock:     { rock: 0, paper: 0, scissors: 0 },
  paper:    { rock: 0, paper: 0, scissors: 0 },
  scissors: { rock: 0, paper: 0, scissors: 0 }
};
```

---

## 5.7 모델 성장 기록

학생은 학습 모델을 저장하고 점수를 비교할 수 있습니다.

사이트 설명상 저장되는 것은 사진이 아니라 다음과 같은 요약값입니다.

- 모델 이름
- 날짜
- 점수
- 평균 이미지 등 요약 숫자

브라우저 로컬 저장만 사용한다고 명시되어 있습니다.

### 구현 선택

- 소량 모델: `localStorage`
- 평균 이미지 배열과 기록이 많음: `IndexedDB`

사이트가 정확히 어느 API를 쓰는지는 공개 화면만으로 확정할 수 없습니다.

‘우리 반 저작물 시장’은 웹앱에서 끝나지 않고 실제 친구 작품을 서로 이용하는 활동으로 확장됩니다.

핵심은 학생이 **허락 조건이 넓을수록 사용이 늘고, 조건이 없거나 불명확하면 사용하기 어렵다**는 것을 경험하게 하는 것입니다.

이는 저작권 교육을 금지 중심에서 **허락과 공유 규칙 이해** 중심으로 바꿉니다.

개인정보처리방침에 따르면 다음을 명시합니다.

- 회원가입 없음

- 광고 없음
- 카메라는 가위바위보 실험실에서만 사용
- 모델 저장만 브라우저 로컬 저장 사용
- HTTPS
- CSP 적용
- 외부 코드·이미지·글꼴 차단
- iframe 삽입 방지
- 카메라 외 위치·마이크·결제 기능 비활성화

## 7.1 학교용 웹앱 관점에서 배울 점

이 서비스의 보안은 복잡한 인증 시스템으로 해결한 것이 아니라 **애초에 수집하지 않는 구조**로 해결합니다.

이 원칙은 교실 도구에서 매우 강합니다.

```
학생 개인정보가 필요하지 않다
→ 계정을 만들지 않는다
→ 서버 DB가 필요하지 않다
→ 유출될 학생 데이터도 최소화된다
```

# 8. UI/UX 패턴 분석

## 8.1 공통 패턴

네 앱은 대체로 다음 구조를 반복합니다.

- 상단에 앱 번호
- 명확한 제목
- 1, 2, 3, 4 형태의 단계 네비게이션
- 각 단계마다 하나의 핵심 행동
- 즉시 결과 시각화
- 인쇄 / 학습지 연결
- 하단에 개인정보·라이선스 안내

이 반복성은 학생이 새 앱으로 넘어가도 사용법을 다시 익히지 않게 합니다.

---

## 8.2 버튼 문구

버튼이 추상적인 ‘실행’, ‘확인’이 아니라 행동형입니다.

예:

- 숫자로 바꾸기
- 지금 그림 담기
- 맞춰 보기
- 학습시키기
- 지금 화면 기록하기
- 시험 다시 시작
- 스티커 인쇄

학생 대상 도구에서는 이 방식이 훨씬 좋습니다.

---

## 8.3 단계형 정보 공개

복잡한 개념을 한 화면에서 모두 설명하지 않고 **활동 순서에 맞춰 단계별로 필요한 정보만 보여 줍니다.**

특히 가위바위보 실험실에서

```
데이터 수집
→ 평균 모습
→ 판정
→ 시험
→ 개선
```

을 순서대로 공개하는 방식은 다른 AI 교육 도구에도 그대로 적용할 가치가 있습니다.

## 백엔드

관찰상 별도 애플리케이션 서버나 사용자 DB가 필요하지 않습니다.

## 프런트엔드에서 필요한 브라우저 API

| 기능 | 가능한 API |
|---|---|
| 그림 그리기 | Canvas / Pointer Events |
| 사진 업로드 | File API |
| 이미지 축소 | Canvas drawImage |
| 픽셀값 읽기 | getImageData |
| 카메라 | MediaDevices.getUserMedia |
| 전후면 전환 | facingMode |
| 모델 저장 | localStorage 또는 IndexedDB |
| 인쇄 | window.print + @media print |
| 활동지 | 정적 PDF/DOCX 링크 |

> 라이브 페이지 소스를 직접 열어 확인하지 못했기 때문에 프레임워크, 실제 파일명, 함수명은 확정하지 않습니다.

# 11. 이 서비스가 잘 푼 복잡한 문제

## 11.1 “AI는 데이터를 학습한다”를 눈에 보이게 만들기

해결 방식:

```
사진
→ 24×24
→ 숫자
→ 같은 클래스 평균
→ 비교
→ 판정
```

추상적인 AI를 **학생이 볼 수 있는 중간 산출물**로 계속 바꿉니다.

---

## 11.2 데이터 편향을 설명하는 문제

해결 방식:

- 좋은 데이터를 보여 주기
- 나쁜 데이터를 일부러 보여 주기
- label 오류 삽입
- 데이터 수 감소
- 새로운 카드/새로운 손으로 시험

즉 설명 문장 대신 **모델이 실제로 틀리게 만듭니다.**

---

## 11.3 초등학생 개인정보 문제

해결 방식:

- 로그인 없음
- 원본 사진 서버 업로드 없음
- 얼굴 대신 손 권장
- 카메라 수동 활성화
- 탭을 닫으면 데이터 삭제
- 로컬 모델 저장도 사진 대신 요약 숫자

---

## 11.4 웹과 종이 수업의 단절 문제

해결 방식:

모든 주요 앱에서 인쇄 또는 워드 학습지를 연결합니다.

즉 웹앱은 완결된 교재가 아니라 **교실 활동을 여는 도구** 역할을 합니다.

# 12. 한계와 개선 가능성

## 12.1 실제 AI와의 구분을 더 분명히 할 필요

가위바위보 모델은 공개 설명상 평균 이미지 기반 분류기에 가깝습니다.

초등 수업에서는 오히려 장점이지만, 교사가 이를 CNN과 같은 현대 이미지 분류 모델과 동일한 것으로 설명하면 오개념이 생길 수 있습니다.

### 권장 문구

> 이 실험실은 기계학습의 핵심 과정인 ‘데이터를 모으고, 특징을 비교하고, 시험하고, 다시 개선하기’를 단순한 계산으로 보여 주는 학습 모델입니다.

---

## 12.2 사회적 영향 탐색이 상대적으로 약함

[6실05-05]는 AI가 만들어지는 과정뿐 아니라 사회적 영향 탐색도 포함합니다.

현재 네 앱의 중심은 원리 체험입니다.

추가 가능:

- 잘못된 분류가 사람에게 미치는 영향
- 데이터 대표성 문제
- 자동 판정의 책임 주체
- 생성형 AI와 저작권 연결

---

## 12.3 접근성

추가로 확인하거나 개선하면 좋은 항목:

- 키보드만으로 모든 격자 조작 가능한지
- 색상 외에 레이블/패턴으로 상태를 구분하는지
- screen reader에서 canvas 대체 설명 제공 여부
- 버튼 최소 터치 크기
- 고대비 모드

# 13. 다른 학교용 웹앱에 재사용할 핵심 원칙

1. **기능보다 학습 흐름을 먼저 설계한다.**
2. 학생이 보는 중간 계산 결과를 숨기지 않는다.
3. 정답뿐 아니라 실패 사례를 설계한다.
4. 학습 데이터와 시험 데이터를 분리한다.
5. 개인정보는 보호 정책보다 “수집하지 않는 구조”가 먼저다.
6. 웹 활동 뒤에 기록지·인쇄 활동을 붙인다.
7. 저장이 필요하면 원본보다 최소한의 요약 데이터만 저장한다.
8. 단계형 UI를 여러 앱에서 일관되게 반복한다.
9. 교과 성취기준을 단순 표기하지 말고 실제 조작과 매핑한다.
10. 학생용 버튼은 기능명이 아니라 행동 문장으로 쓴다.

# 14. school-coding-study에서 특히 참고할 가치가 높은 부분

## A. AI 원리 학습용 미니앱 설계

- 픽셀 → 데이터
- 카드 규칙 → 분류
- 평균 이미지 → 학습
- 시험 → 혼동표
- 재학습 → 모델 개선

이를 각각 작은 독립 활동으로 구현한 뒤 하나의 학습 흐름으로 묶는 구조가 좋습니다.

## B. 서버 없는 교실 앱

학교 Wi-Fi, 계정 발급, 개인정보 문제를 줄이기 위해 **정적 배포 + 클라이언트 계산 + 로컬 저장** 구조를 적극 검토할 수 있습니다.

## C. ‘망가뜨리기’가 있는 AI 교육

정상 작동만 체험시키지 않고

- 데이터를 줄인다
- 편향시킨다
- 레이블을 틀리게 한다
- 낯선 입력을 준다

와 같은 실패 실험을 기본 기능으로 넣는 것이 좋습니다.
